# Dashboard guide

Run `python -m streamlit run app.py` from the repository root after installing
`python -m pip install -e ".[dashboard]"` on top of the base dependencies.

1. **Mission overview:** choose an example or generated checkpoint on the left.
   Empty metrics mean there is no associated record for that exact path.
2. **Live simulation:** choose a seed; Start/reset opens a real Gymnasium
   `rgb_array` environment; Pause/resume suspends steps; Stop closes it. Speed
   is an approximate browser update target. The eight displayed signals are
    observation values, not physical SI units. Start/reset replays the same seed.
   The four Q bars are real network estimated discounted returns for the state
   **before** the last applied action, not action confidence or current-state
   telemetry.
3. **Training lab:** submit validated hyperparameters. Refresh is automatic
   while the page is open; stdout/errors and a downloadable CSV remain on disk.
    Stop finishes the current episode before saving final weights. There is no
    exact training resume/pause. PID and launch time are stored on disk. After a
    restart, a missing worker PID is shown as stale/orphaned; PID reuse is not
    a reliable reattachment mechanism.
4. **Performance analytics:** choose a training log, rolling window, and
   evaluation artifact. Training native returns and independent safe-landing
   outcomes have different meanings. Evaluations show sample counts and a 95%
   Wilson score interval; for publication prefer at least 100 episodes. When
   both native and shaped runs have identical recorded training methods except
   shaping, a matched native-return comparison and CSV download appear.
 5. **Experiment comparison:** select runs. Only different configuration leaves
    appear above the rolling-return curves. A controlled configuration requires
    matched seed, budget, agent, environment and held-out evaluation protocol;
    a matched but short 300-episode comparison remains **exploratory evidence**.
6. **Model checkpoints:** inspect architecture, local creation time, size and
   metadata. Evaluate starts a subprocess without updating weights. The example
   checkpoint is a copy of the successful recorded policy; a `best.pt` was
    selected by highest periodic mean *native* return, not safe-landing count.
   New runs save numbered checkpoints at the configured interval; the journey
   offers same-run episodes 100/300/500/750/900 when present. For actual failed
   frames, run `python scripts/evaluate.py --checkpoint examples/best_native.pt
   --episodes 100 --seed 40400 --failure-gallery 3`; the first three
   non-landings are stored as frame strips with seeds/outcomes/steps and shown
   here for the selected checkpoint. A 100-episode CPU capture on 2026-10-18
   produced seeds 40403, 40406 and 40414 (all off-pad/unsafe).

Only load local models you trust. Check `logs/output_ui_*.txt` for training
errors and `logs/dashboard_evaluation.txt` for evaluation errors. Missing logs
show empty states; older experiment records may not have worker status or
per-episode duration columns.

The source ZIP includes three curated historical runs, their best checkpoints,
and independent result CSV/JSON artifacts. This is real evidence, not example
data generated by the UI. Training writes periodic evaluation CSV rows as each
evaluation completes; the Training lab displays the latest saved checkpoint
and the latest available evaluation result.
